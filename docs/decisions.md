# 통합 결정사항

대화 기록과 현재 코드 기준으로 통합한 프로젝트 결정 목록

## 핵심 결정

| 결정 | 이유 | 상태 |
|---|---|---|
| `label`은 선택지의 0-based 인덱스 | 숫자와 불확실성 의미의 혼동 방지 | 유지 |
| 불확실성은 선택지 내용으로 판정 | 행마다 선택지 위치가 달라질 수 있음 | 유지 |
| 명시적 사실과 객관적 시각 근거 우선 | 편향된 추론 위험 감소 | 유지 |
| 기준선 대비 변경 행 수와 agreement 기록 | 프롬프트 변경 영향 확인 | 유지 |
| 행별 사후 라벨 패치 금지 | 누수·재현성 문제 방지 | 유지 |
| 원격 실행 자료의 영속 보존 | 임시 환경 종료 후 원인 분석 보장 | 유지 |

## 실험 운영

- 모델과 프롬프트를 동시에 변경하지 않음
- 후보 모델은 smoke → validation/A-B → full inference 순서로 비교
- JSON-only 강제보다 parser hardening과 final-line parsing 우선
- 결과 CSV, raw output, 실행 요약, 설정을 후보별로 보존
- 공개 점수만으로 일반화 성능을 확정하지 않음

## Shadow Validation

- public-source 기반 자료만 사용
- 민감 속성은 질문·라벨·프롬프트에 사용하지 않음
- 이미지 권리 확인 전 pixel source 사용 금지
- 자동 생성 pending 문항은 사람 검수와 gold label 확정 전 기준셋으로 사용하지 않음

## 보류 항목

- 최종 성능이 가장 높은 모델 확정
- 공유 Reasoner 원본 프롬프트·parser·결과 매핑 확인
- Shadow Validation gold label과 freeze 결과 확정
- 원격 재현 번들의 완전성 확인
- 외부 자료의 라이선스와 공개 가능 범위 최종 확인
